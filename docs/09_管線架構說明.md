# 09 管線架構說明

> 本章所有案例均為虛構。本章只說明架構與資料流，不附程式碼。

## 一句話

把一批雜亂的工廠文件，變成「可以交給外部團隊做知識檢索、又把可識別風險降到約定門檻以下」的語料，同時保留製程知識與事件的先後順序。

整條管線的核心設計只有一條：**還原金鑰和交付物永遠分開。** 會產生實名的東西（對照表、殘留報告、候選表）只在機密區流動；交付樹裡只放已去識別化的語料和說明。

## 各步驟做什麼

| 步驟 | 做什麼 | 輸入 | 輸出 | 機密等級 |
|---|---|---|---|---|
| ⓪ 對照表產生器 | 把實名清單、通訊錄、補充名單、各類資料檔整合成一張對照表，給每個人、公司、地名、機種發代號；也產生正則遮罩規則 | 實名清單與資料檔 | 對照表（替換字典、正則規則、人名主檔等分頁） | **還原金鑰** |
| ① 盤點 | 走訪原始資料樹，用白名單決定每個檔進不進流程；認不得的類型一律排除（漏判的後果是少做，不是外洩） | 原始資料（唯讀） | 檔案清單與摘要 | 含原始路徑，機密 |
| ② 抽文字 | 把 Office、PDF、文字檔抽成純文字，可中斷續跑；掃描型 PDF 另走 OCR | 檔案清單 | 原文 JSONL、失敗清單 | **含實名**，機密 |
| ③ 去識別化主程式 | 查表替換、正則遮罩、日期位移、路徑去識別化，並產生演變鏈用的欄位（文件類型、日期範圍、提到的代號） | 原文、對照表 | 去識別化語料 | 可交付（通過閘門後） |
| ④ 殘留掃描 | 拿對照表當答案卷回頭掃語料，再加格式類檢查（電話、身分證、帳號、門牌、未位移日期）；分 L1／L2／L3 三層 | 語料、對照表 | 殘留報告與摘要 | 報告含實名，機密 |
| ④a 未知人名偵測／④b 證據聚合 | 不看對照表，純粹找「長得像人名」的字串（④a），再把全庫證據聚合起來判斷（④b） | 語料 | 候選表 | 含實名，機密 |
| ④c 三錨點人名候選 | 用三種鄰近錨點（職稱在前、緊鄰已知代號、緊鄰聯絡資訊遮蔽標記）找表外的人 | 語料 | 候選表 | 含實名，機密 |
| ④d 固定反掃 | 把幾種「字典以外」的反掃固定下來，每次交付前都跑：常見英文名、英文稱謂後的人名、拼音人名、簽核欄中文姓名、客戶欄後的英文字 | 語料、對照表 | 候選表 | 含實名，機密 |
| ⑤ 打包與交付報告 | 通過閘門才打包；產生交付說明（數字由程式實測填入）與給委託方看的報告 | 語料、殘留摘要 | 交付樹、交付報告 | 交付樹可交付 |
| ⑥ 圖片分流 | 用文字區塊偵測與 OCR 把圖片分成高風險、待複核、放行 | 圖片 | 分流清單 | 機密 |

## 去識別化主程式的處理順序

順序本身就是規則的一部分，排錯會出現「代號被二次替換」「日期被位移兩次」這類問題。

1. 清掉控制字元。
2. **原文層比對**：在簡轉繁之前，先用原始寫法比對一次，避免轉換器依上下文把字轉成別的字，導致字典對不上。
3. 簡轉繁與字形正規化：字典和語料走同一個正規化函式。
4. **查表替換**：保護詞排最前面（整詞保留），其餘依字面長度由長到短；命中處先換成哨兵。
5. 正則遮罩：電話、身分證、帳號、地址、檢測報告編號、證書編號、縮寫黏編號等格式類。
6. 料號規則。
7. 日期位移：已位移的先用哨兵保護，避免二次位移。
8. 哨兵還原成代號。
9. 需要看最終文字的規則：簽核欄單字姓、姓氏＋職稱、敬稱。
10. Email 帳號遮蔽、合併相鄰的重複代號。

**公開手冊模式**：清單上的第三方公開設備手冊只跑第 5 與第 7 步（正則與日期），不套字典。原因是手冊上下文會讓代號被反推（例如廠牌名被換成客戶碼後，讀者看產品型號就知道是哪家）。掃描端必須同步把這些文件的命中記為 L3。

## 閘門

| 閘門 | 條件 | 不過的後果 |
|---|---|---|
| 殘留掃描 | **L1 = 0** | 打包與交付報告拒絕打包 |
| 語料新鮮度 | 殘留掃描必須在語料產生之後跑、篇數一致 | 拒絕打包 |
| 交付樹檔名 | 不得出現對照表、金鑰這類關鍵字 | 拒絕打包 |
| 語料逐列 | 不得含哨兵字元或原始絕對路徑 | 拒絕打包 |
| 交付夾內容 | 說明、附表的內容逐檔過對照表字面掃描 | 命中即視同洩漏 |
| 抽樣上界 | 人眼抽樣漏遮率低於約定門檻（見 06） | 不交付 |

殘留掃描只能證明「表裡有的都遮了」。表外的漏遮靠 ④a～④d 的候選表加人工判讀，再補資料檔、回到對照表產生器重跑——這是一個迴圈，不是一次性步驟。

## 資料分級

| 等級 | 內容 | 規則 |
|---|---|---|
| 還原金鑰 | 對照表、實名清單、含實名的資料檔、帳本 | 只有對照表產生器可寫；其他工作線唯讀；絕不推上任何遠端版控 |
| 稽核（等同金鑰） | 殘留報告、各種候選表、替換統計、待裁決命中 | 只放稽核區；不可貼進對話或報告 |
| 原文 | 抽出的原文 JSONL、原始檔案清單 | 與原始資料同級，不可和交付物放同一層 |
| 交付物 | 去識別化語料、交付說明、同義詞表 | 只有這一類可以離開機密區 |
| 方法文件 | 本方法文件 | 不含實名，提交前跑守門程式 |

## 代號的設計

代號格式是「類別前綴＋四位數碼－虛構名」，例如 C0001-Xxxx、PSN0001-Xxxx。四位數碼與出現次數無關——照出現次數編號，會讓「0001 號」直接洩漏誰是組織裡溝通量最大的人。前綴與人名分層見 01 章。

## 改動的標準流程

1. 改資料檔一律另存新檔（日期後綴），程式自動挑最新版。
2. 對照表產生器先在副本乾跑，檢查計數。
3. 去識別化主程式在受影響的子集上乾跑，和上一版逐篇比對，差異必須全部可解釋。
4. 舊版語料與進度檔改名保留，再全量重跑。
5. 殘留掃描、未知人名偵測、固定反掃全部跑過，L1 = 0。
6. 打包，交付說明交給獨立審稿者對實測。
