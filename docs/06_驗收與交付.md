# 06 驗收與交付

> 本章所有案例均為虛構。

## 三層殘留掃描的真實含義

殘留掃描把語料分成三層。名字聽起來很安全，但每一層實際上驗的東西比名字窄，交付前要知道它們各自的盲點。

| 層 | 名義 | 實際上在驗什麼 | 陷阱 |
|---|---|---|---|
| L1 高危 | 實名、Email、企業名殘留，必須為 0 | **對照表裡的字面有沒有換掉** | 不在表裡的人完全隱形（詳見完整版） |
| L2 待判 | 規則要補或可能誤傷 | 格式類規則（電話、門牌、未位移日期等）的命中 | 容易被程式自己產生的標記灌爆（詳見完整版） |
| L3 刻意不換 | 人工裁決過、刻意保留的字面 | 佔位提醒，例如公開手冊裡保留的廠牌名 | 掃描端與處理端的範圍不一致時，會被誤算成 L1 |

**L1 = 0 是必要條件，不是充分條件。** 它證明的是「名單執行到位」，不是「語料裡沒有人」。這兩件事之間的差距，就是完整版「涵蓋範圍」整節在講的事。

## 建議的驗收判準

一、**L1 = 0**：名單內的字面全部換掉。

二、**抽樣漏遮上界**：從遮蔽標記密集的區域用固定種子抽 30 篇，由人眼判讀，計算每篇平均漏遮人名數，要低於事先約定的門檻（例如從每篇約 0.5 個降到 0.1 個）。這是最直接回答「夠不夠好」的指標，也最適合寫進合約。

三、**通訊錄型文件整批不交付**。這類文件實名密度最高、對製程知識的貢獻最低，直接排除的效益遠高於繼續補規則。但要有心理準備：排除通訊錄型文件大約只解決一半的真人字面，另一半散在一般文件裡，它不是銀彈。

四、**剩餘風險用合約與存取控制封頂**。規則層有天花板，這是事實，不是藉口。

## 交付前檢查清單

- [ ] L1 = 0
- [ ] 抽樣漏遮上界達標
- [ ] 對照表版本與語料版本對得起來（同一輪產出）
- [ ] 進度檔與對照表的時序正確，沒有混用兩代對照表（詳見完整版）
- [ ] 交付樹裡沒有：對照表、殘留報告、候選表、待裁決命中、替換統計、檔案清單（manifest）
- [ ] 交付樹裡沒有作廢版本；作廢的要改名並移出
- [ ] 檢查檔案時間戳分布；若某一年佔比超過六成，要在說明裡註明修改時間不可信
- [ ] 替換統計要看分項，不要只看總數；字數類的處理量（例如裁切掉的字數）不可和替換次數混在同一張表
- [ ] **掃描端與處理端的處理範圍一致**：處理端若對某類文件只套部分規則（例如公開手冊只遮電話地址），掃描端也要同步把那類文件的命中記為「刻意不換」，否則會把刻意保留的字面誤報為漏遮
- [ ] **交付包與檔名不得帶出已遮的字面**：專案代號、資料夾名、檔名裡的城市縮寫或公司縮寫，本身就是被遮的資訊；交付物一律改用中性名稱或化名
- [ ] 交付說明寫清楚：位移了什麼、遮了什麼、刻意不遮什麼

## 機密分級

| 等級 | 內容 | 放哪 |
|---|---|---|
| 同還原金鑰 | 對照表、實名清單、補充人名分層、代號變更表 | 金鑰區（只有對照表產生器可寫） |
| 同還原金鑰 | 殘留報告、未知人名、人名候選、裁決表、替換統計、待裁決命中 | 稽核區 |
| 含實名 | 人工歸戶、衝突裁決、姓氏職稱強制、拼音別名、地名表等資料檔 | 應放機密區，不可放在一般工具資料夾 |
| 含實名 | 抽出來的原文、原始檔案清單 | 機密區，不可和交付物放在同一層 |
| 可交付 | 去識別化語料、交付說明、同義詞表 | 交付樹 |
| 可交接 | 本方法文件 | 一般區 |

**對照表絕不可隨語料交付。** 殘留報告與候選表含未遮實名，等級與對照表相同。

## 交付樹紀律

- 作廢的語料立刻改名（加上「作廢＿日期＿原因」）並移出交付樹，不要留在名為「交付」的資料夾裡。
- 含實名的資料檔不要放在沒有機密標記的資料夾。
- 每次交付前掃一次交付樹，確認只有該有的東西。
- 交付樹裡**每一個檔的內容**都要過實名掃描，不只語料、不只檔名。說明書樣板、附表、報告都是人寫的敘述，最容易夾帶實名（詳見完整版）。打包與交付報告應內建這一步（詳見完整版），新加進交付夾的任何檔型都要確認有被掃到。
- 交付說明提到「哪些東西不在這包裡」時，用代號講，不要用實名講——排除清單本身就是一張實名清單。
- **每一類前綴各跑一次錨點反掃**（詳見完整版）：客戶、供應商、人名、機種、地址，加上路徑裡的資料夾名。只掃一類就停，是常見的漏洞（詳見完整版）。
- **半遮公司名掃描**（詳見完整版）：把代號後面接法定後綴（有限公司、股份有限公司等）的尾巴列出來看。
- 另一條工作線（不經過對照表產生器的其他資料處理工作）的抽取結果（例如圖框、簽核欄）可以當成獨立答案卷交叉比對（詳見完整版）。
- 交付說明要交給沒參與撰寫的審稿者逐條對實測（詳見完整版），並且明確要求他找「還能指認出是哪家公司」的字面，不只看措辭。

## 語料本身的已知限制（要寫進交付說明）

- **id 撞號**：路徑遮蔽後，不同檔案的去識別化路徑可能長得一樣；同一相對路徑在不同來源根下各有一份也會撞。**主鍵要用 key 欄，id 只當顯示。**
- **日期位移**：文件中的日期經過位移，絕對時間不可信。
- **修改時間（mtime）**：若檔案複製時時間戳塌陷，不能拿來當時序依據；整理期間被重新存檔的檔案，原修改時間已不可考，應置空。
- **裁切**：幾何檔（STEP 等）只留檔頭，內容被裁掉。
