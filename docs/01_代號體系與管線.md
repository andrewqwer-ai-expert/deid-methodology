# 01 代號體系與管線

這一章說明一條工廠文件去識別化管線長什麼樣子、代號怎麼設計，以及整條管線都要守住的七條硬原則。後面各章提到的程式，一律用本章定義的通用名稱。

## 管線：七段程式

| 段 | 通用名稱 | 做什麼 | 產出 |
|---|---|---|---|
| 0 | 對照表產生器 | 從實名清單、通訊錄、補充名單建立對照表，為每個實體發代號 | 對照表（**還原金鑰**） |
| 1 | 盤點 | 掃描來源資料夾，決定哪些檔案進語料 | 檔案清單（白名單骨架） |
| 2 | 抽文字 | 把 Office、PDF、文字檔抽成一行一份文件的 JSONL | 抽文字輸出（原文，仍含實名） |
| 3 | 去識別化主程式 | 查表替換、正則遮罩、日期位移 | 去識別化語料 |
| 4 | 殘留掃描 | 交付閘門，把殘留分成 L1／L2／L3 三級 | 殘留報告（機密） |
| 4a～4d 輔助 | 4a 未知人名偵測、4b 證據聚合、4c 三錨點人名候選、4d 固定反掃 | 找「對照表以外」的漏網人名與實體 | 候選表（機密） |
| 5 | 打包與交付報告 | 產出交付包與 README、交付報告 | 交付樹 |
| 6 | 圖片分流 | 圖片另案處理 | — |

第 0 段每次重建都是「整張重來」，不是增補帳本；第 3 段之後的所有程式都拿同一張對照表當依據。

## 代號前綴

代號格式是「前綴＋四位數碼－虛構名」。例如客戶「乙一公司」在語料裡會變成 `C0001-Xxxx` 這種形式，`Xxxx` 是完全自創的虛構名，與真實企業無關，也不是原名的替身。四位數碼與出現次數無關——照出現次數編號，會讓 0001 號直接洩漏「誰是溝通量最大的人」。同一個名稱每次都得到同一個代號。

| 前綴 | 對象 | 可還原 |
|---|---|---|
| ORG | 我方集團實體（示例：甲一公司、甲集團） | 是 |
| C | 客戶（示例：乙一公司、乙二公司） | 是 |
| S | 供應商（示例：丙一公司、丙二公司） | 是 |
| MDL | 機種（示例：X1、X2） | 是 |
| PRD／PRJ | 產品類型／專案編號 | 是 |
| LOC | 地名（示例：甲市、乙市） | 是 |
| PSN | 人員主檔（管理層，示例：人員甲、人員乙） | 是 |
| WK | 作業層人員 | **否（刻意關上的門）** |
| ROLE | 共用信箱、角色帳號 | 是 |
| SUR | 姓氏碼（只知道姓、不確定是誰時的保守遮罩） | 部分 |
| EXT | 外部聯絡人（客戶、供應商、認證機構的窗口，示例：Ms. Cherry） | 是 |
| MAT | 料號 | 是 |

**人名分層原則**：管理層發 PSN，必要時可以用金鑰回溯「誰決策、誰簽核」；作業層發 WK 碼，同一人跨文件仍是同一個碼（演變鏈追得動），但永遠對不回本人。客戶、供應商、認證機構等外部單位的窗口（含外部廠商工程師、外部技術顧問）一律發 EXT（外部聯絡人），不進內部的 PSN／WK 分層；PSN／WK 只用於我方人員。

## 七條硬原則

**一、長度降序。** 字典依字面長度由長到短排序再匹配。否則短字面（公司簡稱）會先吃掉長字面（含地名的完整登記名稱）的一部分，長字面永遠輪不到，結果就是「代號＋某某電子有限公司」這種半遮半露。

**二、哨兵兩段式。** 命中處先換成一個內部記號（哨兵），全部掃完才把哨兵換回代號。這樣任何代號都不會被後面的規則二次替換（日期被位移兩次、代號裡的字被當成人名再遮一次）。代價是：所有「要看最終文字」的規則（姓氏＋職稱、敬稱補遮）必須排在哨兵還原之後。

**三、人工裁決只記錄、不替換。** 字面有歧義時（同一字面對到多個化名、或本身就是常用詞），對照表產生器把化名寫成「待人工裁決」，去識別化主程式整條跳過。**這不是忘了裁決，而是程式拒絕替你猜。** 例外：人名與姓氏職稱兩類照樣替換——漏掉一個人的代價比誤遮大。

**四、字典字面與語料文字走同一個正規化函式。** 例如繁簡轉換、外語字表、逐字修正表，兩邊都要先過同一道處理再比對。少了這一步，字典裡的繁體字面接不住語料裡的簡體寫法，隔壁供應商都換掉了，它沒換。

**五、對照表與語料一一對應。** 對照表就是那一批語料的還原金鑰。換表就要整批重跑，不可以續跑（詳見完整版「混代語料」）。

**六、輸出檔名永不原地覆蓋。** 對照表、語料、報告一律帶日期；同一天重跑就加 -2、-3。

**七、含實名的東西不進交付樹。** 對照表、殘留報告、候選表、待裁決命中、替換統計，機密等級全部等同對照表。

## 資料檔類型

對照表不是手寫的，是對照表產生器從下列資料檔「整張重建」出來的。各團隊命名不同，功能大致如下：

| 資料檔 | 用途 |
|---|---|
| 實名清單、通訊錄 | 人員、組織的基本來源 |
| 補充名單（補充人名分層、補充公司表、外部聯絡人） | 從語料回頭補進來的人與企業；人名要分管理層與作業層 |
| 別名表（拼音、英文名、羅馬字） | 同一人的各種寫法，指向同一個代號 |
| 人工歸戶 | 把系統判成兩個人的寫法合併成一人，或修正部門 |
| 衝突裁決表 | 同一字面對到多個化名、或與常用詞同形時的人工裁決（指定、不遮、改類別），每筆寫理由 |
| 姓氏職稱強制 | 「姓＋職稱」寫法的強制遮罩清單 |
| 保護詞 | 整詞保留、不讓子字串被字典吃掉的詞（材料名、地名寫法等） |
| 觀察清單 | 還沒有定論、先觀察命中情況的字面 |
| 代號變更表 | 代號改發或合併的紀錄，讓前後版本對得起來 |
| 帳本 | 需要跨版本固定配碼的對象（例如外部聯絡人、料號、單字姓）的「鍵→代號」紀錄；對照表產生器讀它、只追加不改號 |
| 公開文件清單 | 只套正則與日期、不套字典的第三方公開文件 |
| 同義詞表 | 同一詞的不同寫法對照，給檢索端做同義擴展；不含實名，可隨語料交付 |

輔助工具「守門程式」：方法文件或任何要對外的檔案提交前，拿對照表字面掃一遍，命中身分類字面就擋下（詳見完整版）。它不屬於管線本身。
